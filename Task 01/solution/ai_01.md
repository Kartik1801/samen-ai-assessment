# what is pthread_cond_signal & pthread_cond_wait

## pthread_cond_signal

pthread_cond_signal is a POSIX threads function that unblocks at least one thread currently waiting on a specific condition variable (cond). If no threads are waiting, it has no effect. It should be called while holding the associated mutex to guarantee predictable scheduling and prevent lost signals.

### Key Aspects of pthread_cond_signal

**Functionality:** Wakes up one thread blocked in a `pthread_cond_wait` or `pthread_cond_timedwait` call.

**Performance:** If multiple threads are waiting, it wakes up at least one, but not necessarily all (use `pthread_cond_broadcast` for all).

**Mutex Handling:** While not strictly required for the function to return 0, it is highly recommended to hold the associated mutex when calling `pthread_cond_signal` to prevent lost wakeups.

**Error Handling:** Returns 0 on success, or an error number (e.g., EINVAL if the condition variable is invalid).
Ordering: The highest priority waiting thread is usually signaled first.

### Usage Example

```c
pthread_mutex_lock(&mutex);
// Change the state that the waiter is waiting for
pthread_cond_signal(&cond); // Signal that the state has changed
pthread_mutex_unlock(&mutex);
```

### Important Notes

**Spurious Wakeups:** Always use `pthread_cond_signal` in conjunction with a while loop checking the actual condition predicate, because woken threads might wake up even if the condition is not actually met.

**Missing Signals:** If `pthread_cond_signal` is called before a thread enters `pthread_cond_wait`, the signal is lost.

```c
// Correct usage
pthread_mutex_lock(&lock);
while (!condition_is_true) {
pthread_cond_wait(&cond, &lock);
}
// Do work
pthread_mutex_unlock(&lock);
```

## pthread_cond_wait

pthread_cond_wait is a POSIX threads function that blocks a thread until a specific condition is signaled, atomically unlocking the associated mutex and suspending the thread. It is used to pause execution until a shared variable changes, preventing busy-waiting. Upon returning, the thread automatically re-acquires the mutex.

```c
#include <pthread.h>

// Must be called with 'mutex' locked
int pthread_cond_wait(pthread_cond_t *cond, pthread_mutex_t *mutex);
```

### Key Behaviors

**Atomic Operation:** The function atomically releases the mutex and blocks the thread. This prevents a race condition where a signal is sent between unlocking the mutex and blocking.
**Automatic Relock:** When the function returns, the thread has re-acquired the mutex, allowing safe access to shared data.
**Spurious Wakeups:** A thread can wake up from pthread_cond_wait even if no signal was sent (spurious wakeups). Therefore, always re-evaluate the condition predicate in a while loop, not an if statement.
**Cancellation Point:** If a thread is cancelled while waiting, it will re-acquire the mutex before exiting to allow proper cleanup handlers to run.

### Typical Usage Pattern

```c
pthread_mutex_lock(&lock);
while (condition_is_false) {
pthread_cond_wait(&cond, &lock);
}
// Do work while holding the lock
pthread_mutex_unlock(&lock);
```

### Common Errors

- **Unowned Mutex:** Failing to lock the mutex before calling pthread_cond_wait results in undefined behavior (usually error EPERM).

- Using if instead of while: Failing to re-check the condition after waking up can lead to race conditions.
Recursive Mutexes: Using recursive mutexes with condition variables is not recommended and can cause deadlocks
